# OpenWrt Board Finder

Небольшая утилита для Windows: находит платы с OpenWrt в локальной сети
широковещательным UDP-запросом и открывает их веб-интерфейс двойным кликом.

Это настольная часть демона `locator`, работающего на плате (он отвечает на запросы
обнаружения по UDP-порту 23, сообщая тип платы, её идентификатор, MAC-адрес,
версию прошивки и название приложения).

---

## Возможности

- Опрашивает **все** активные IPv4-интерфейсы одновременно.
- Показывает IP, MAC, клиентский IP, версию прошивки и название приложения.
- **Двойной клик по строке** открывает `http://<ip-платы>` в браузере по умолчанию.
- Если в ответе нет MAC-адреса, он запрашивается через ARP (`SendARP`).
- Рассылка идёт и на `255.255.255.255`, и на широковещательный адрес подсети —
  некоторые адаптеры молча отбрасывают первый вариант.
- Сканирование всегда завершается: есть жёсткий общий предел времени.

## Требования

| | |
|---|---|
| ОС | Windows 10 / 11 (x64) |
| Среда выполнения | [.NET 8.0 **Desktop** Runtime](https://dotnet.microsoft.com/download/dotnet/8.0) |
| Сборка | .NET 8 SDK или Visual Studio 2022 (17.8+) |

> Приложение собирается как framework-dependent. Если .NET 8 Desktop Runtime не установлен,
> Windows сама покажет окно «framework not found» со ссылкой на загрузку — код приложения
> при этом не выполняется, поэтому проверять наличие среды выполнения изнутри бессмысленно.
> Чтобы обойтись без установки .NET, публикуйте self-contained сборку (см. ниже).

## Сборка

```bash
git clone https://github.com/<ваш-аккаунт>/Finder.git
cd Finder
dotnet build -c Release
```

Или откройте `Finder.sln` в Visual Studio 2022 и нажмите **F5**.

### Публикация

Один файл, требует установленный .NET 8:

```bash
dotnet publish -c Release -r win-x64 --self-contained false ^
  -p:PublishSingleFile=true
```

Self-contained (среда выполнения на целевой машине не нужна):

```bash
dotnet publish -c Release -r win-x64 --self-contained true ^
  -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true
```

Результат — в `bin/Release/net8.0-windows/win-x64/publish/`.

## Использование

1. Убедитесь, что на плате запущен демон `locator`, а ПК находится в том же L2-сегменте
   (широковещательный пакет не проходит через маршрутизатор).
2. Запустите `Finder.exe` — сканирование стартует автоматически.
3. Кнопка **Refresh** — повторное сканирование.
4. **Двойной клик** по плате открывает её веб-интерфейс.

### Брандмауэр

При первом запуске Windows Defender попросит разрешение. Разрешите доступ в
**частной** сети — иначе ответы плат будут отброшены и список останется пустым.

## Протокол обнаружения

Все поля — «сырые» байты, преобразования порядка байт нет.
Поле `length` — размер **всего** пакета, включая завершающий байт контрольной суммы.
Контрольная сумма подобрана так, чтобы сумма всех `length` байт была `0 (mod 256)`.

### Запрос (ПК → широковещательный адрес, UDP 23)

| Смещение | Размер | Значение | Смысл |
|---|---|---|---|
| 0 | 1 | `0xFF` | `TAG_CMD` |
| 1 | 1 | `0x04` | длина пакета |
| 2 | 1 | `0x02` | `CMD_DISCOVER_TARGET` |
| 3 | 1 | `0xFB` | контрольная сумма |

В эфире: `FF 04 02 FB`.

### Ответ (плата → ПК)

| Смещение | Размер | Смысл | Присутствует при |
|---|---|---|---|
| 0 | 1 | `TAG_STATUS` = `0xFE` | всегда |
| 1 | 1 | длина пакета | всегда |
| 2 | 1 | `CMD_DISCOVER_TARGET` = `0x02` | всегда |
| 3 | 1 | тип платы | `length > 5` |
| 4 | 1 | идентификатор платы | `length > 5` |
| 5–8 | 4 | клиентский IP (адрес, с которого плата нас видит) | `length > 9` |
| 9–14 | 6 | MAC-адрес | `length > 15` |
| 15–18 | 4 | версия прошивки | `length > 19` |
| 19–82 | 64 | название приложения, с завершающим нулём | `length > 83` |
| последний | 1 | контрольная сумма | всегда |

Полный ответ — 84 байта.

Название приложения декодируется как **UTF-8** и обрезается по **первому** нулевому байту:
всё, что лежит в 64-байтовом поле после терминатора, игнорируется.

Версия прошивки выводится как четыре десятичных байта через точку (`1.2.3.4`).
Если ваша сборка `locator` упаковывает это поле иначе, поправьте одну строку в `ProcessResponse()`.

### Тайминги сканирования

| Этап | Таймаут |
|---|---|
| Ожидание первого ответа | 5 с |
| Ожидание следующих ответов | 1 с |
| Жёсткий предел всего сканирования | 15 с |
| Максимум плат | 256 |

## Диагностика

| Симптом | Причина / решение |
|---|---|
| «No boards found.» | Брандмауэр блокирует UDP/23, плата в другой подсети, или не запущен `locator`. На плате: `/etc/init.d/locator status` |
| «Could not open any UDP socket (port 23 may be in use).» | UDP-порт 23 занят другой службой на всех интерфейсах. Приложение уже пробует эфемерный порт; если и это не помогло — остановите конфликтующую службу. |
| MAC показан как `N/A` | Ответ короткий (без поля MAC), и ARP-запрос не удался — нормально, если платы ещё нет в ARP-кэше. |
| Колонка Application пуста | Ответ короче 84 байт — плата не передаёт название приложения. |
